## 2. 逐条详述

### R1 · KS 检验在这里不成立 🔴

**现象**：用户步骤 4 要求"对当前潜变量与各子任务/总任务的潜空间正态分布做 Kolmogorov–Smirnov 检验，以不可信度路由"。

**证据（四条独立的问题）**：

1. **维度**：KS 是 1 维检验。`d=32` 的潜变量没有 1 维 CDF 可比；逐维做 32 次再取最小 p 值 = 32 重比较，power 崩且选择偏差严重。
2. **时序自相关（最致命）**：窗口内相邻帧高度相关，有效独立样本数远小于帧数。KS 的 p 值假设 i.i.d.，在自相关下**严重反保守**——实测会稳定得到 `p≈0`，于是"永远不像任何子任务"，路由恒走 CAP，直接违背 A3。
3. **形状假设**："潜空间是正态分布"是先验假设，不是后验事实；VAE 的后验通常是重尾/多峰的。
4. **多重检验**：N 个子任务各一个 p 值，取最小者必须校正，否则阈值不对应任何名义错误率。

**后果**：若照做，判别器会退化为常量函数（恒"不认识"或恒"认识某个"），方案整体失效，且失败症状会被误读为"VLA 不行"。

**处置**：换成 **conformal p 值**（`02` §4.2 C1）：任意 1 维非一致性分数 + 校准集 → 分布无关、有限样本有效的 p 值，阈值 τ 直接对应误拒率，且天然处理"在 N 个子任务里选一个"。KS 保留为 1 维诊断图。
**成本**：几乎为零（实现更简单）。**副产品**：这是本方案最可辩护的方法贡献。

---

### R2 · 潜变量可能根本不可分 🔴（go/no-go）

**现象**：整个方案依赖"潜空间里不同相位是分开的"。这没有任何先验保证：
- VAE 的潜变量是为**重建**服务的，方差可能被光照、纹理、相机视角占满；
- `stack_bowls` 的相邻相位（"手伸向碗" vs "手已抓住碗"）视觉差异极小，可能只差几帧、几个关节角；
- 更糟的是**相位是渐进的**：不存在天然边界，标签本身来自 Flora 的 8 Hz 采段（时间分辨率 125 ms），边界误差 0.3–1.0 s 是协议粒度（`FLORA_CAPTIONER_LABELING.md` §2.3）。**如果标签自身在边界处模糊 0.3–1.0 s，那么任何判别器在边界附近都不可能准，而边界附近恰好是最需要判别的地方。**

**后果**：若不可分，则 R1/R3/R4 的所有修补都没有意义。

**处置（必须先做，成本 1 天）**：**G2 可分性探针**（`05` §2.2）——不训 VAE，先用冻结视觉特征（ResNet/DINO 类）+ 关节状态，训一个线性/浅层探针做子任务分类，报告：
- balanced accuracy vs 随机基线 `1/N`；
- 混淆矩阵（错分是否集中在相邻相位 → 说明是"渐进而非错误"）；
- 只用 q、只用图像、两者都用 三档对比；
- 边界 ±25 帧内的准确率单独报（这才是路由真正在乎的区域）。

**通过阈值**：`balanced acc ≥ 1/N + 15 pt` 且"q + 图像"优于任一单独模态。不通过 → 转 §5 方案。

---

### R3 · 文本 K-means 给不出"子任务" 🟠（已决议：接受 S1）

**现象**：步骤 2 说"用 K-means 对各任务所有帧的 embedding 聚类，得到 N 个子任务"。

**证据（本文实测，`scripts/caption_structure.py`）**：

- f35 的标签是**段级**的（31,968 段），"帧的 embedding"实际是把段 caption 广播到帧上，所以 K-means 其实是在**语言空间**里聚。这一点本身不是错，但决定了聚类结果的语义。
- 集内唯一率 **96.8%**（重复仅 3.2%），全库唯一率 **38.3%**：**子任务在集内是单向推进的时序相位，跨集才复用为语义类。**
- 实测 k-means：k=4/5 退化为 `pick`(40.9%)/`place`(47.3%)/`move`(6.7%) 的**动词族**；k=8/12 开始按左右手与物体切，且出现 5 段、2 段的退化簇；簇内平均余弦只有 **0.48–0.56**（很不紧）；质心前 4 词全是 `the / on / on_the / of`（停用词污染）。

**后果**：簇是"动作语义类"，它在每个 episode 里**反复出现、位置不定**，因此**不能当进度信号**。若把它当进度用，会让 R9（抖动）与 A2 一起失败，而失败原因会被误判成"判别器不准"。

**处置（2026-11-24 用户决议后修正）**：**保持用户的做法**（整句 → embedding → K-means），接受 S1。理由是架构自洽：你的 pipeline 里"具体哪个物体、哪一侧"由 **VLM 看当前帧接地**，路由器只需回答"现在做什么动作"，这正是 S1 的能力范围。所以 S1 的缺陷**不影响你的架构**，它只限制了"把演示原句直接吐给 VLA"（`T+oracle` 式）这种用法。

**保留两条预期**：① prompt 内容更粗、更依赖接地 → 接地成本成为关键路径（R13）；② 将来若要省掉 VLM，必须先补 S2（`02` 附录 A）。

仍需执行的三条卫生要求：L2 归一化、小写化去句号、功能词抑制并检查质心可读性；且**在全库上聚一次**共享语义词表，而非 35 个任务各聚一次。

### R4 · 每子任务一个 VAE 🟠（已决议保留 V1；我此前的反对作废一半）

**现象**：步骤 3 说"对 N 个子任务和整个任务，**分别**做 VAE 编码"→ 约 `Σ(N_T+1) ≈ 350` 个 VAE。

**用户决议**：保留 V1。

**我原来说了两条，现在必须分开算账**：

| 我原来的反对 | 现在是否成立 | 说明 |
|---|---|---|
| ① 每子任务 ~5,900 帧，样本不够 | ✅ **仍然成立** | 需工程约束：96×128、d=16、4 层 conv、强增广、β 扫描（`02` §3.2） |
| ② 350 个潜空间互不可比，判别"无法提问" | ❌ **不成立，我推错了** | 该反对只在"用潜空间距离比较"时成立。用户选定的 **conformal p 值**只要求每子任务有**自己的标量分数**（如 `−ELBO_k`），且每个 `p_k` 在自己的校准集上**各自均匀分布**；均匀分布的 p 值之间天然可比，`argmax_k p_k` 就是该框架下的标准多分类判据 |

**因此我原来那句"用户设想的核心判别动作在 V1 下是未定义的"是错的。** 正确说法：**V1 下判别必须用"逐模型似然 + conformal"，不能用"潜空间距离"**——用户恰好选了前者，所以自洽。已记入 `DECISIONS.md` D2。

**V1 剩下的真风险只有三条，都有抓手**：

1. **过拟合**：用 `02` §3.2 的容量约束 + §3.4 的三项失败判据（留出 ELBO gap / 状态重建 MAE / 校准 p 值均匀性）逐模型筛，不过就降级为"无模型"。
2. **工程量**：350 个模型 ≈ 20–35 GPU·h，需队列脚本 + 统一超参（6c 现在 6 卡全空闲，一夜可完）。
3. **似然不可比性的残余**：conformal 让 p 值可比，但**若某个 VAE 严重欠拟合**，它会给校准集外的样本也打高似然 → 该类 p 值系统性偏大 → 挤掉真实类。对策：把"欠拟合检测"作为准入条件，并监控各类触发频率是否失衡。

**顺带的好处**：未见任务（官方 42 里约 7 个）没有自己的 VAE，路由天然落到 `task`/`cap` —— **OOD 兜底是架构自带的**。

### R5 · VAE 重建 ≠ 判别 🟠

VAE 的 ELBO 不奖励可分性。若不干预，潜空间会把方差分配给最省重建代价的方向（背景、光照）。
**处置**：① 状态重建损失加权（≥2.0），因为 14 维关节状态是子任务身份最强线索；② 加辅助子任务分类头（多任务损失）；③ 训练完必做**线性探针**验证可分性，不通过就不进入路由。

---

### R6 · A2 主张已被既有数据逆向挑战 🔴（最深的科学风险）

**现象**：方案的立论是"路由到正确的子任务 prompt 能提升 SR"。而既有 ⑤ 档已经做了内容正确的 oracle：

| 档 | 语言条件 | SR |
|---|---|---|
| ① | 只有总任务 prompt | **64.0 %** |
| ⑤ | Flora 段级 caption（**内容 oracle**）逐窗口注入 | **60.0 %** |

差 1 局（噪声量级）。**"给对的语言"这件事本身没有换来增益。**

**但先别下结论 —— ⑤ 档有一处致命缺陷**：它的 oracle 时间线来自**单条参考集**按 `step/592` 线性映射，闭环里机器人一旦偏离演示进度，caption 就与真实阶段错位（⑤ 档自己的边界说明里写了）。所以它是"**内容 oracle + 时间错位**"，而不是真正的 oracle。**"内容 oracle + 时间对齐"从未被做过。**

**处置（1 天，最优先）**：`01` H2 判决实验——用**仿真状态**定义 `stack_bowls` 的相位（"已叠几个碗"），做成真正的时序 oracle，与 `T` 臂对比（各 25 局，纯 VLA，不碰任何学习组件）。
- 若 oracle-timed ≈ `T` → **A2 放弃**，转 §5 效率/兜底路线；
- 若 oracle-timed 显著 > `T` → 判别器有明确的收益空间，值得投 1.5–2 周。

**这个实验不需要训任何模型，却是全项目最高性价比的一步。**

### R7 · 分布偏移与 OOD 🟠

- 官方评测 42 个基础任务 / 54 配置，我们的训练数据覆盖 **35** 个 → **约 7 个任务从未出现在训练数据里**（`ROBODOJO_BRIEF_CN.md` §8.1 待确认，但方向明确）。
- 闭环策略会把自己的偏差放大：路由判错 → prompt 错 → 状态漂移 → 更不像任何相位 → 升级 CAP。**误差级联是单向的。**
- 25 个评测布局固定，但跑次之间场景/初始状态不一致（同配置两次运行逐布局仅 14–19/25 吻合，`EVAL_4CELL_RESULTS.md` §9）。

**处置**：① 校准集必须来自**闭环** rollout 而非开环演示（`03` §4）；② 显式引入 OOD/背景类，而非"不属于任何相位"这个隐含类；③ 滞回 + 冷却（R9/R10）阻断级联；④ 单独报告未见任务子集的表现。

### R8 · 统计功效 🟠（单位已改，原功效表作废）

**旧口径（已废）**：单任务 25 局，95% CI ≈ ±19 pt，同配置重复运行极差可达 20 pt，于是推出"要 150–225 局/臂"。

**新口径（900 局，2026-11-24 实测）**：

- 非配对：基线 9.56%，**n=900 可检测 ≈ +4.2 pt 绝对（相对 +44%）**；检测 +5 pt 需 662 局/臂，+8 pt 需 283 局/臂。
- **配对：分辨率约 1 pt**。三次对照的不一致对只有 80–89 对（占 900 局的 9%），故净不一致 ≥11 对（≈1.2 pt 绝对）即 p<0.05。

**后果**：**"多堆场次"不是解，改用配对才是解**。绝对阈值（+10 pt 等）在 9.56% 基线下等于"翻倍"，必须废掉（`01` §5 J1/J2 已改）。

**处置**：36 任务 × 25 layout = 900 局，**同 layout 配对 + McNemar 为主**；报净不一致对数与 p，不报点估计差；筛选阶段可只用 6 个受害格（150 局）看方向。

### R9 · 抖动与动作块边界 🟡

π0.5 输出 50 步动作块（≈2 s @25 fps），而慢层判别是 1–2 Hz。若语言条件在 chunk 内部改变，同一块动作由两个 prompt 指令生成，行为会撕裂。
**处置**：确认帧数（m=3–5）+ 最小驻留（1 s）+ prompt latching（只在 chunk 边界切换）+ 记录切换次数。
**另需核实**（`ROBODOJO_BRIEF_CN.md` §7 遗留项）：评测模板 `action_steps=16` 与 π0.5 的 50 步块如何对齐——这个数若没对齐，所有臂的 SR 都会被同一个 bug 污染。

### R10 · CAP 的成本 🟠（已从合作者论文取得实数，风险性质改变）

**现象**：CAP（GPT-6 Astra）作为兜底，其调用成本决定 A3 是否成立。

**实数**（`CAP_LATENCY_NOTE.md`，来自 [arXiv 2609.38537](https://arxiv.org/abs/2609.38537)）：

| 项 | 值 |
|---|---|
| 单次调用延迟 | **39.86 s**（dense locomotion 实测均值；推理期间物理暂停） |
| RoboDojo Hybrid 成功率 | **24/50 = 48%**（Direct 13/50 = 26%） |
| 每集调用次数（中位，RoboCasa） | Hybrid **108**、Direct **85** |
| 单集 token | Hybrid 624.8M、Direct 1,132.3M（50 实例合计） |
| 全程 CAP 单集墙钟（推算） | **≈ 72 min = 150× VLA-only** |

**三个后果（都改变了原方案）**：

1. **A3 变成"真但空洞"**：72 min vs 32 s 是 135× 的差距，这个对照太容易赢，审稿人会认为不构成对照。**应改述为**："CAP 级 system-2 兜底的边际成本约为单集 VLA 预算的 **1.38 倍/次**，因此闭环里最多只能被调用 **O(1) 次**；我们把'何时调用'变成一个可校准的统计决策。" 这比"我们比全程 CAP 快"有信息量。
2. **"墙钟 ≤1.25×"与"允许 CAP 兜底"数学上互斥**：36 s 的预算容不下一次 39.86 s 的调用。所以 J4 必须拆成 J4a（零触发，≈1.1×）与 J4b（OOD 子集，≤1 次/集，≈2.5×）。原 J5 的"CAP 触发率 < 20%"直接违反 J4a，已废弃。
3. **CAP 在已知任务上救不了 SR**：论文 Hybrid 只有 48%，低于我们 VLA-only 的 76–84%。所以 CAP 分支的正当性**只在 OOD**（官方 42 任务里约 7 个未见），不能当作"判别器失准时"的默认落点——否则 R7 的误差级联会把每一集都推到 CAP，墙钟直接 12×。

**处置**（写进实现约束）：
- CAP 语义改为**按 (任务, 布局) 摊销**：首次进入时最多一次，产出（计划或接地后的 prompt）缓存复用，同一集内不重复调用；
- CAP 触发必须是**显式的 OOD 事件**，不是"所有子任务 p 值都低"的默认分支；
- 评测必须分开报：CAP 触发次数、CAP 总耗时、"CAP 零触发子集"的 SR。

**论文的正面价值**：它明确把"**何时介入、何时交还控制权**"列为开放问题（原文 *"effective cooperation still requires Astra to recognize when to intervene and when to return control to the policy"*）——**这就是本项目的立项理由，应直接引用在动机段**。同时说明存在轻微撞车风险：该文做了混合控制但没有做"统计化的介入判据"，我们的差异点必须落在**calibrated 的介入决策**上，而不是"用 Astra 兜底"本身。

### R13 · 效率主张基本失效（实测 VLM 只占墙钟 +3.8%）🔴

**我原来的论证**：用旧链路的"27B 经隧道 3.4–5.6 s/次"，推出 VLM 主导墙钟（45 min vs 12 min），于是"效率的支点是把接地换成 2B 小模型"。

**实测推翻（交接文档 §6.7）**：

| 配置 | VLM 前向/格（25 layout） | 单格墙钟 |
|---|---|---|
| interval=50（chunk 级） | 375 次 | 31.9 min |
| interval=10（step 级） | **1,881 次（5×）** | 33.1 min（**+3.8 %**） |

VLM 单次 **0.32 s**（A6000 上的 2B，`<vlm-server>:8101`）；**瓶颈是仿真步进 ≈1.9 step/s·env**，不是模型调用。

**三个后果**：

1. **我的整套墙钟模型（`02` §5.3、`03` §5.1）作废**——那些表是按 3.4–5.6 s/次算的。
2. **A3 对 `T+Vnow` 失去意义**：少调 VLM 最多省 3.8%，不构成论点。**A3 只剩对 CAP 的一条**（39.86 s/次，`CAP_LATENCY_NOTE.md`），而这条 `T+Vnow` 也满足。
3. **"接地换小模型"不再是我们能主张的贡献**——2B 已经上线，是既有条件，不是我们的发现。

**处置**：
- 效率主张**从主贡献降为附带说明**（可写进 limitations 或消融，不作为 headline）；
- 若仍要保留一条效率主张，只能写成"**大多数步不需要刷新 prompt，因此连 3.8% 也可以不付**"——但它太小，不足以支撑一个 claim；
- **本项目的价值必须完全落在 SR 与 OOD 兜底上。**

### R14 · 「刷新频率」与「动作视界」被混淆，latching 策略失去依据 🟠（新增）

**现象**：`T+Vnow-int10` 的实现是**把 action chunk 截断到 10 步**（`PHYSBRAIN_VLM_INTERVAL_STEPS`）。所以 interval=10 同时改变了：

- prompt 刷新周期（10 vs 50 步）；
- **有效动作视界**（10 步 vs π0.5 训练时的 50 步）。

**后果**：由此得出的"越频繁刷新越好"是**混淆结论**——它混合了"prompt 陈旧度的代价"与"动作视界被截短的收益/代价"。交接文档 §9.1 自己也指出要改**异步刷新**（图像每步更新、caption 只在 chunk 边界生效）来解耦。

**对本方案最直接的冲击**：我在 `02` §5.2 写的「prompt latching，只在 chunk 边界切换」——按现有数据，**chunk 边界刷新（interval=50）恰恰是显著有害的那一档（p=0.020）**，而更频繁的刷新打平。**我们的默认设计选择目前没有依据。**

**处置**：把「刷新频率 vs 动作视界」的解耦实验提为 **G2.5**，**排在 VAE 训练之前**（成本 ~2 格评测、半天）：
- 臂 1：interval=50（= 既有 `T+Vnow`）
- 臂 2：interval=10（= 既有 `int10`）
- 臂 3：**异步**——VLM 每 10 步前向，但 caption 只在 50 步边界生效（动作视界保持 50）
- 读法：若臂 3 ≈ 臂 2 > 臂 1，则"prompt 越新越好"，latching 应取消；若臂 3 ≈ 臂 1 < 臂 2，则"动作视界缩短"才是收益来源，与 prompt 无关——那我们的路由设计要重做。

高严重度理由：这条混淆直接决定路由器的**切换时机**设计，而切换时机是方案里唯一还能产生 SR 差异的旋钮。

## 3. 相关工作定位与新颖性

已核到的相关方向（外部链接，仅作定位参考）：

- **Code-as-Policies 线**：[CaP-X (ICML 2026)](https://icml.cc/virtual/2026/poster/66369) 提供了"用编码 agent 做操作"的基准与改进框架；[PromptBook (NeurIPS 2023)](https://dev.neurips.cc/virtual/2023/77271) 说明 CAP 的瓶颈在技能库与提示工程，而不在代码生成本身。→ 对应本方案的 CAP 兜底臂。
- **不确定性驱动的策略选择**：[When to Act, Ask, or Learn: Uncertainty-Aware Policy Steering](https://browse-export.arxiv.org/pdf/2602.22474) 已经把"何时执行/何时求助/何时学习"形式化为不确定性驱动的转向问题。→ **与我们的三路路由高度重叠，是最需要区分的邻居。**
- **conformal 预测用于机器人规划**：[Probabilistically Correct Language-Based Multi-Robot Planning Using Conformal Prediction](https://par.nsf.gov/biblio/10574146/media/xml) 已在语言规划上用 conformal 给概率保证。→ 说明"conformal + 语言条件"不是空白，但尚未见到用在 **VLA 的语言粒度路由**上。

**新颖性判断（诚实版）**：

| 主张 | 新颖性 |
|---|---|
| 潜空间典型性判别做子任务路由 | 中：判别本身不新（OOD/selective prediction 的常规搬用） |
| conformal p 值替代 KS 做分级升级 | **中高**：把"何时升级到 CAP"变成有有限样本保证的拒识问题，这一组合我没找到直接对手 |
| "语言条件时间对齐 vs 内容正确"的解耦实验 | **高**（作为实证贡献）：⑤ 档的负结果提供了一个干净的对照前提 |
| SR–墙钟帕累托前沿的量化 | 低-中：工程贡献，但审稿人喜欢 |

**结论**：这不是"新能力"级的工作，是"新组合 + 一个干净的实证纠正"级的工作。作为会议/期刊的一篇（中等偏上目标）成立；作为"必须比 SOTA 高很多"的旗舰主张不成立。**必须把 R6 的实验结论放进摘要，无论正负。**
