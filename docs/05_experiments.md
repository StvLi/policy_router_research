## 2. Gate 细节

### 2.1 G0 / G-1：语言结构

产出物：
- `phase_index.json`：每 `(episode, task)` 的相位序列 `[k=1..n]` + 对应 caption + 时间区间；
- `phase_chain.json`：每任务的"典型相位链"（DTW 对齐后），给出相位 k 的语义代表句；
- `caption_clusters.json`：全库 S1 语义簇（N=5–8）；
- 审计报告：N 的分布、簇内余弦、单例簇比例、重叠区剔除率。

人审：35 个任务各看 1 条相位链，确认"读了能明白任务怎么推进"。**读不懂就是失败**（这是最便宜的质量关）。

### 2.2 G2：可分性探针（go/no-go）

为什么不能直接训 VAE：VAE 要几小时，探针只要几分钟，且能**独立**回答"信息在不在"这个更根本的问题。若冻结特征都分不开，学出来的 VAE 潜空间也不会凭空分开。

设置：

| 项 | 值 |
|---|---|
| 特征 | 冻结视觉骨干（ResNet-18 / 可用 DINO 类）× 3 视角 concat，+ 14 维状态（标准化）× h 帧 |
| 标签 | G0 的子任务簇 id |
| 切分 | **按 episode 不相交**（沿用 `SUBTASK_VLM_SPEC.md` §7 的切分纪律），另留未见任务测试集 |
| 探针 | 线性（逻辑回归）+ 浅层 MLP 各一次 |
| 必报 | ① balanced acc vs `1/N`；② **边界 ±25 帧内的 acc**（单独！这是路由真正在乎的区域）；③ 混淆矩阵的相邻相位集中度；④ q-only / img-only / both |

判读：
- `bal.acc` 高但**边界 ±25 帧内**低 → 相位可分但边界模糊 → 路由必须带滞回，且必须接受"边界附近必然误判"（这在指标上要容忍）。
- both ≈ img-only → **状态没起作用**，说明 14 维 q 的编码或权重有问题（`04` R5），先修这个再训 VAE。

### 2.3 G4：conformal 校准与风险-覆盖曲线

- 非一致性分数：`s_k(z) = Mahalanobis(z, μ_k, Σ_k)`（Ledoit-Wolf 收缩），或 `−log p_k(z)`；
- 校准集：**闭环 rollout + CAL-A 标签**（`03` §4），与测试 episode 不相交；
- 扫描 `τ_sub`，得到 (VLM 调用率, 路由准确率) 曲线；同理 `τ_task` 得 (CAP 率, 兜底准确率)；
- OOD 评估：把**未见任务**的样本作为正类，算 AUROC。

## 3. 闭环臂（G5）

| 臂 | 代号（并入 `NAMING.md`） | 语言条件来源 | 目的 | 必要性 |
|---|---|---|---|---|
| A | `T` | 总任务固定 | 下基线（9.56%） | 必须 |
| B1 | **`T+Vnow`** | chunk 边界注入（既有，已跑完 900 局） | 上基线之一（7.00%，已被证明有害） | **已完成，直接引用** |
| B2 | **`T+Vnow-int10`** | step 级注入（既有，已跑完 900 局） | 上基线之二（9.22%，与 T 打平） | **已完成，这是我们的真正对手** |
| C | `T+oracle` | 时序正确 oracle 阶段 | H2 判决 / 理论上界 | 必须（先 1–2 格） |
| D | `T+R` | 路由器（**无 CAP**） | 主张 A1 / A2 | 必须 |
| E | `T+R+cap` | 路由器 + CAP 兜底 | 主张 A3 | 必须 |
| F | `cap` | 全程 CAP | 效率对照 | **只需 5–10 局标定**：按 39.86 s/次 × ~108 次/集 ≈ 72 min/集，跑满 150 局需 7.5 天 |
| G | `T+R*` | **路由到检索模板原文，不经过 VLM 接地** | **消融：区分"路由"与"VLM 接地"的贡献** | 强烈建议 |
| H | `T+R@27B` | 路由 + 27B 接地（而非 2B） | 效率主张的反例对照（`04` R13） | 建议（25 局即可） |

G 臂是全设计里最容易被忽略但最重要的一条：它把"D 臂的增益"分解为"选对了子任务"与"VLM 把子任务接地到当前场景"两部分。**没有它，无法回答审稿人"这不就是加了个分类器"的质疑。**

H 臂则是效率主张的守门员：它证明"快"不是因为少调了两次，而是因为**接地模型小了一个量级**。

**开跑前必须先测**：2B 与 27B 的单次接地延迟（含网络/隧道/批处理）。这两个数字直接决定 J3/J4 是否可达，也决定 H 臂值不值得跑满 150 局。

其它消融（离线做即可，不必上闭环）：
- KS vs conformal（复现 R1 的失败模式，作为对照图）；
- S1 语义类 vs S2 相位；
- 全局 VAE vs 每任务 VAE（V3 vs V2）；
- q-only / img-only / both；
- 无滞回 vs 有滞回（报切换次数与 SR）。

## 4. 统计功效（决定性约束）

> ⚠️ **本节下方的表是按"单任务 25 局"推的，已作废**。正确的功效口径见 `PRIOR_RESULTS_20261124.md` §2.2–2.3：
> **基线 9.56%；900 局非配对可检 +4.2 pt（相对 +44%）；配对 McNemar 分辨率约 1 pt（净不一致 11 对即 p<0.05）。**
> 保留本节只是为了说明"为什么绝对不能再用 25 局下结论"。

### 4.1 单臂置信区间

| 局数/臂 | p≈0.7 时 95% CI | p≈0.8 时 95% CI |
|---|---|---|
| 25 | ±18.0 pt | ±15.7 pt |
| 50 | ±12.7 pt | ±11.1 pt |
| 100 | ±9.0 pt | ±7.8 pt |
| 150 | ±7.3 pt | ±6.4 pt |
| 225 | ±6.0 pt | ±5.2 pt |
| 300 | ±5.2 pt | ±4.5 pt |

与既有实测一致（他们记的 ±19 pt @ n=25 略保守，因为 p 更接近 0.5）。

### 4.2 要"证明优于"需要多少局（两臂，α=0.05 双侧，power=0.8，非配对）

| 待检测差异（例） | 需要局数/臂 |
|---|---|
| 5 pt（80 vs 75） | **1,091** ❌ 不现实 |
| 10 pt（80 vs 70） | **290** |
| 10 pt（76 vs 66） | **319** |
| 12 pt（76 vs 64） | **225** |
| 14 pt（90 vs 76） | **109** |
| 15 pt（80 vs 65） | **135** |

### 4.3 结论与建议

1. **5 pt 级别的结论不可承诺**。项目主张必须瞄准 **≥15 pt** 的效应量。
2. 筛选期用 **100 局/臂**（只能看方向，不能下结论）；定稿期用 **≥225 局/臂**（可支持 12 pt 主张）。
3. **配对设计**（同一批布局、同一 seed）能显著降低所需局数——相同布局下两臂的成功高度相关，McNemar 只看不一致对。建议：**150 局固定布局 × 3 seed**，报配对 McNemar + bootstrap CI，等价功效通常好于 225 局非配对。但**配对不代表可以只看 25 局**：既有实测同配置两次运行逐布局仅 14–19/25 吻合，配对相关性没有想象中高。
4. **预注册阈值**：在跑之前把 J1–J6（`01` §5）与所有阈值写死，避免事后挑。

## 5. 核心图（这篇工作最终应该长什么样）

**主图：风险-覆盖曲线**

```
SR
│            ●  oracle-timed (C)      ← 理论上界
│        ●───●
│      ╱  ●D  T+R
│    ╱  ●  ●E  T+R+cap
│  ●───────  A  T（固定成本，横线）
│●  B  T+V（高成本，低 SR）
└──────────────────────────── VLM/CAP 调用率 →
        ↑ 我们要的是"在低调用率处取得高 SR"
```

预期形态：`D` 臂在调用率 5–15% 时 SR 接近 `C` 臂；`B` 臂调用率 100% 但 SR 不高于 `A`。
**若 `A` 与 `C` 重合（H2 被推翻），这张图的主信息就变成"SR 与调用率无关"，项目转效率论文。**

副图：
1. **墙钟柱状图**（4 臂：`T` / `T+V` / `T+R+cap` / `cap`）；
2. **切换次数 vs SR**（证明滞回有效）；
3. **相位混淆矩阵**（边界 ±25 帧单独标出）；
4. **KS 与 conformal 的对照**（KS 的 p 值分布图 —— 预期它在自相关下集中到 0，这就是 R1 的可视化证据）；
5. **OOD AUROC**（未见任务）。
