## 1. 问题

VLA（π0.5）在推理时吃什么语言，是个未被解决的工程-科学问题。现有三种喂法各有硬伤：

| 喂法 | 语言粒度 | 硬伤 |
|---|---|---|
| 只给总任务（`T`） | 整任务一句话 | 长程任务里语言条件全程静止，VLA 只能靠视觉自己推断进度；单句无法消解"现在该动哪个物体" |
| 每步/每窗口让 VLM 现生成子任务（`T+V`） | 帧级自由生成 | ①贵：3.4–5.6 s/次，闭环 45 min/25 局 vs 12 min；②抖：逐帧重写导致语言条件漂移；③已被实测证明**不涨点** |
| Flora 段级 caption 逐窗口注入（`T+oracle`） | 段级真值 | 内容对、**时间错**（单条参考集线性映射 `step/592`），实测 60% ≈ 无增益 |

**本项目要回答的问题**：
> 能否用一个**便宜的、以自身观测为输入的判别器**，在推理时决定"此刻该用哪一级语言条件"——细粒度子任务、还是退回总任务、还是升级到 CAP——从而在不增加墙钟的前提下提升成功率？

注意问题的主语是 **"此刻该用哪一级"**，不是"生成更好的句子"。这个区分是本文档 §4 立论的基础。

## 3. 这三条证据把方案逼到了哪里

**证据 1（最关键）：⑤ 档告诉我们，"给对的语言内容"不产生增益。**
oracle 内容（Flora 真值 caption，逐窗口变化）60% vs 只有总任务 64% —— 差 1 局，噪声量级。**如果连"语义正确"的语言条件都不涨点，那么"更准确地选出子任务 prompt"这一条路径，在 prompt 内容维度上就已经没有收益空间了。**

**证据 2：涨点来自训练数据，不来自推理时提示。**
74%（子任务打标训练）vs 60%（不打标训练）vs 64%（Flora 打标训练）= +14 pt / +4 pt。**推理时的语言条件几乎不影响 SR；训练数据的子任务结构才影响。** 这解释了证据 1。

**证据 3：VLM 在线注入是负贡献或无贡献，且成本 3.75×。**
60–64% vs 64%，墙钟 45 vs 12 min。**花 3.75 倍时间买不到点。**

### 由此得到的张力

如果三条都成立，那么用户设想中 A2（超过只给总任务）就**不是"再加一个更好的 prompt"能实现的**——它在原理上就没有空间。真正的空间只剩两个：

1. **⑤ 档的失败不等于"时序正确的 oracle"也失败。** ⑤ 的 oracle 时间线来自单条参考集按 `step/592` 线性映射，闭环里机器人一旦偏离演示进度，注入的 caption 就与真实阶段错位（⑤ 档自己的边界说明里写了这一点）。**"内容 oracle + 时间错" 与 "内容 oracle + 时间对" 是两个完全不同的实验，后者从未被做过。** 这恰好就是本方案要提供的判别器的核心能力：**判断"现在是第几阶段"**。
2. **CAP 兜底的价值在两个失败模式上**：任务本身超出 VLA 能力（官方评测 42 任务里约 7 个从未出现在训练数据中），以及闭环漂移到 VLA 不认识的区域。前者用 prompt 永远救不了，后者用 prompt 也救不了——只有升级。

所以方案的重心必须移动：

> **从"给更好的语言" → 移到 → "判断进度、判断是否超纲、决定何时升级"。**

## 4. 被重写的假设

原设想的三条期望改写成下面三条**可证伪**假设。每条都写清"什么结果算推翻"。

### H1（进度判别可行）— 可离线快速死刑

> 存在一个便宜的潜空间编码器 `F`，其潜变量 `z` 能区分同一任务内的不同**子任务簇**，且判别精度显著优于随机。

- 检验：离线。取 f35 中每个 episode 的 `(o_h, q_h)`，以 G0 的子任务簇 id 为标签，训练/线性探针/密度模型，报告子任务分类 top-1 与 balanced accuracy。
- **推翻条件**：最优线性探针的 balanced accuracy ≤ `1/N + 5 pt`（等于随机）判负；≥ `1/N + 15 pt` 判正；中间为灰区，需加测边界指标（`05` §2.2）后再定。另：若与"仅用关节状态 q"相比，加图像无显著增益，也判负。
- 成本：6c GPU4 上 < 1 天。
- **这是整个项目的 go/no-go。** 理由见 `04` R2。

### H2（时序正确的语言注入有效）— 纯 VLA，最便宜，也最致命

> 当语言条件的内容**和时序都正确**时，SR 显著高于只给总任务。

- 检验：闭环，但**不涉及本方案的任何学习组件**。用"真值进度"驱动 caption 注入，对照臂 = 只给总任务。
- **⚠️ pilot 任务已改**：不要用 `stack_bowls`——它在 900 局实验里是受害最深的格子（T 19/25 → int10 12/25）。应改用注入已显示净正的 **`put_bottles_into_dustbin`（19→22）与 `fold_clothes`（13→16）**（`PRIOR_RESULTS_20261124.md` §2.5）。
- **先验更弱了**：伴随 900 局的结果是"chunk 级注入有害、step 级打平"，所以 H2 现在要否证的是"连**时序正确的** prompt 也不涨点"，而不只是"自动生成的 prompt 不涨点"。
- **推翻条件**：oracle-timed 臂 ≤ 总任务臂 + 噪声（当前噪声量级：25 局 ±19 pt 的 CI，≤4 局不可解释；见 `05` §4 功效表）。
- 成本：~12 min/25 局/臂，两个臂半天。
- **若 H2 被推翻，A2 主张整体放弃**，项目退化为"效率/兜底"论文（仍可做，见 `04` §6 转向方案）。

> 为什么把 H2 排在 H1 前面：H2 不需要训练任何东西，半天出结果，却能一次否掉一半的立项理由。**不要先训 VAE。**

### H3（路由带来帕累托改进）— 最终主张

> 路由策略在 **(SR, 墙钟)** 平面上**支配**两端基线：SR 不劣于「每步 VLM」与「只给总任务」中较好者，墙钟显著低于「每步 VLM」，且在超纲任务上不劣于「全程 CAP」。

- 检验：闭环，≥100 局/臂，多 seed，配对布局，报风险-覆盖曲线（`05` §3）。
- **推翻条件**：在 95% CI 下，路由臂既不优于 T 臂也不优于 T+V 臂，或墙钟优势 < 1.5×。
- 成本：见 `03` §5 预算表。

## 5. 成功判据（写进立项书的口径）

必须同时满足，缺一不算成功：

| 判据 | 阈值 | 为什么是这个数 |
|---|---|---|
| **J1 SR vs `T`（900 局配对）** | **配对净不一致 ≥ 11 对（≈1.2 pt 绝对）且 McNemar p < 0.05** | 基线 9.56% 下 +10 pt 等于翻倍，绝对阈值无意义；配对设计在 900 局下的分辨率约 1 pt（`PRIOR_RESULTS` §2.3） |
| **J2 SR vs `T+Vnow` / `T+Vnow-int10`** | `T+Vnow`：**≥ +2.6 pt**（即先抹平它相对 T 的显著损失）；`int10`：**≥ +1.5 pt 且 p<0.05** | 既有实测：`T+Vnow` 7.00%（比 T 低 2.56 pt，p=0.020）、`int10` 9.22%（与 T 打平，p=0.83） |
| J3 墙钟 vs 「每步 VLM」 | **≤ 0.70×**（接地用 2B 小模型时要求 ≤ 0.35×） | 预算见 `02` §5.3：27B 接地 → 69 s/局 vs 108 s/局 = 0.64×；2B 接地 → 32 s/局 = 0.30× |
| **J4a 墙钟 vs 「只给总任务」（硬）** | **≤ 1.25×，且 CAP 零触发** | 28.8 s → ≤ 36 s，即每局接地总开销 ≤ 7 s。按每局 ~8 次切换算，**单次接地 ≤ 0.4 s**（2B 或异步）；27B 的 4.5 s 做不到 |
| **J4b 兜底子集（条件性）** | CAP **≤ 1 次/集**，允许 ~2.5× 墙钟 | 单次 CAP ≈ 39.86 s ≈ **1.38 倍**单集 VLA 预算（`CAP_LATENCY_NOTE.md` §2），所以"1.25× 墙钟"与"允许 CAP 兜底"在数学上互斥，必须分两条主张 |
| J5 超纲/OOD 兜底价值 | 该子集 SR 不下降，且 CAP 只在 OOD 分支触发 | 已知任务上 Astra Hybrid 仅 48%（< 我们 76–84%），**CAP 救不了已知任务的 SR，只能救 OOD** |
| J6 对比必须同 VLA ckpt、同布局、同 seed 协议 | 硬约束 | 既有教训：不同 num_envs / VLM 端点会让结论反向（`EVAL_4CELL_RESULTS.md` §8） |

统计口径（硬约束，沿用既有纪律）：**≤4 局的差异不作为结论；每臂 ≥100 局或 ≥3 次重复；配对布局用 McNemar；报 CI 不报点估计。**

## 6. 贡献陈述草案（如果三条假设都成立）

1. **首次给出"语言条件的时间对齐"与"语言内容正确性"的解耦实验**：证明 ⑤ 档的负结果来自时序错位而非内容，从而修正"推理时子任务提示无用"这一既有结论。
2. **把"何时换语言条件/何时升级"形式化为潜空间上的选择性预测问题**：用 conformal p 值给出**有限样本有效性**的拒识保证（分布无关），比阈值化的 KS/似然比更可辩护。
3. **给出 SR–墙钟帕累托前沿**：在同一 VLA 上量化"语义判别 + 稀疏升级"相对逐帧 VLM 与全程 CAP 的取舍，并给出 OOD 触发的定量边界。

新颖性定位与相关工作见 `04` §5。

## 7. 不做什么（scope 边界）

- **不改 VLA**：全部对照共用同一 ckpt，路由只改 prompt 与是否升级。
- **不做新数据采集**：只用 f35 + sb100。
- **不在 35 个任务上全量铺开**：先在 6 个"受害格"（算力减半、效应集中）打通，再 2–3 个任务验证泛化，最后才考虑全库。**pilot 用 `put_bottles_into_dustbin` + `fold_clothes`，不用 `stack_bowls`**。
- **不把 CAP 做成主路径**：CAP 只做兜底，触发率是受监控的失败指标。
- **不追求在官方 2100 局协议上出总分**：那是另一个工程问题（缺 kmctl 登录态，见 `ROBODOJO_BRIEF_CN.md` §6），本项目的评测在 ws 的 25/100/150 布局矩阵上完成。
