## 0. 符号与契约

| 符号 | 含义 | 形状 / 取值 |
|---|---|---|
| `o_t` | t 时刻三路相机观测 | `3 × 480 × 640 × 3`（head / left_wrist / right_wrist） |
| `q_t` | t 时刻机械臂状态 | `R^14`（左 6 关节 + 右 6 关节 + 2 夹爪） |
| `h` | 历史长度 | 帧数或时刻集合，`[TBD-5]` |
| `x_t` | 历史观测块 | `(o_{t-h+1:t}, q_{t-h+1:t})` |
| `c_i` | 第 i 段的 caption | 英文单句，`f35` 实测均 15.1 词 |
| `e_i` | caption 的文本向量 | `R^{dt}`，L2 归一化 |
| `T` | 任务 id（35 个之一） | — |
| `N_T` | 任务 T 的子任务数 | `[TBD-3]`，实测相位中位 7、均值 8.9 |
| `k` | 相位索引（时序） | `1..N_T`，**单调** |
| `F` | 潜空间编码器 | `x_t → (μ, log σ²) ∈ R^{2d}`，`d = 32`（建议） |
| `z` | 潜变量 | `R^d`，`z = μ + σ ⊙ ε` |
| `s_k(z)` | 非一致性分数 | 标量，越大越"不像相位 k" |
| `p_k` | conformal p 值 | `[0,1]`，**越大越可信** |
| `τ_sub, τ_task` | 两个拒识阈值 | 由风险-覆盖曲线选定 |
| `π_t` | 当前注入 VLA 的语言条件 | 字符串 |

**在线契约（硬约束）**

```
输入:  o_t (3×480×640×3), q_t (14), 任务 id T
输出:  ① 下一段动作块 a_{t:t+50} ∈ R^{50×14}      —— 由 VLA 给（68–71 ms）
       ② 路由决策 d ∈ {subtask, task, cap}       —— 由判别器给（目标 ≤ 20 ms）
       ③ 当前锁存的语言条件 π_t                  —— 只在切换时更新
副作用: 仅在 d 切换时调用 VLM / CAP（有冷却与最小驻留）
```

## 1. 步骤 1：文字 → embedding

### 候选

| 方案 | 做法 | 评价 |
|---|---|---|
| **T-a** token 级 | 只用 tokenizer，取 token embedding 的均值/末位池化 | 用户字面写法。**不推荐**：没有句向量，池化后被高频功能词主导（实测见 §2.3），语义分辨率低 |
| **T-b** 句向量编码器 | bge / e5 / gte 类，输出 1 个句向量，L2 归一化 | 推荐作为默认 |
| **T-c** VLA 自己的 text encoder | 用 π0.5 的 language encoder 产 e_i | **最优**：子任务向量与 VLA 的指令空间同构，"检索到的模板"是 VLA 真能理解的那一类措辞；可复现性也最好 |

### 必做的预处理（否则 §2 会退化）

1. 小写化、去句末句号（实测 31.0% 带句号、13.2% 首字母大写，风格不统一）。
2. **L2 归一化**后再聚类（句向量各向异性严重，不归一化时余弦被公共主方向吃掉）。
3. 记录每条 caption 的来源 `(episode_id, start_s, end_s, task)`；**用绝对时间戳索引帧，禁止用累计段长推算**（硬约束，来自 `FLORA_CAPTIONER_LABELING.md` §5.1：21.9% 的集存在段重叠，重叠时累计偏移必然错位）。

## 2. 步骤 2：K-means 得到"子任务" `[已定]`

> **用户决议（2026-11-24）**：就是"把整句话变成 embedding，再 K-means"，不需要我在 S1/S2 之间让他做选择。
> 本节改为：**先解释这个做法在产品上到底给了你什么**（§2.1，用真实数据举例），再说清唯一一个后果（§2.2），最后给实现细节（§2.3）。

### 2.1 先明确：句向量 K-means 得到的是什么

输入是**整句 caption**，输出是**动作语义的类别**。用真实数据举个例子（`stack_bowls`，三段来自不同 episode 的标注）：

| episode | 时间 | caption（原始标注） |
|---|---|---|
| A | 1.2 s | `pick up the red bowl from the left side of the table with the left hand` |
| B | 7.4 s | `pick up the green bowl from the right side of the table with the right hand` |
| C | 14.9 s | `pick up the yellow bowl from the middle of the table with the left hand` |

这三句在 embedding 空间里**彼此很近**（同一个动作 = pick up + 同一个对象类别 = bowl），所以会被 K-means 聚成**同一个簇**。但它们在各自 episode 里的**时间位置完全不同**（第 1 步 / 第 4 步 / 第 7 步）。

于是两种"子任务"是：

| | **S1 语义类**（= 你写的做法得到的东西） | **S2 时序相位**（你的做法拿不到的东西） |
|---|---|---|
| 定义 | 语言上同族的一类动作 | 集内第 k 个阶段 |
| 上面三句 | 属于**同一个** S1 簇 | 属于**三个不同**的 S2 相位 |
| 复用模式 | 跨集复用 | 集内单向推进 |
| 实测 | 全库 31,968 段 / 12,242 条不同 prompt = 唯一率 38.3%，平均一条承载 2.61 段 | 35 任务抽样：**集内唯一率 96.8%**（重复仅 3.2%） |
| 数量 | 小（5–8） | 中（7–9，长任务到 27） |

**你的 pipeline 里，S1 就够了 —— 理由见 §2.2。**

### 2.2 唯一需要知道的后果 `[风险 R3]`

你的架构是"**路由给出子任务 → VLM 生成 language prompt → 注入 VLA**"。也就是说：

- 路由器只负责回答"**现在该干什么动作**"（pick / place / move / handover）；
- "**具体哪个物体、哪一侧**"由 VLM 看当前帧去接地（grounding）。

这正是 S1 的能力范围。所以 **S1 + VLM 接地 是自洽的，不需要 S2。**

代价有两条，必须写进预期：

1. **路由不能精确告诉 VLA"这是第几步"**。若以后想省掉 VLM、直接把演示里的原句吐给 VLA（即 `T+oracle` 那种用法），那时才需要 S2。
2. **prompt 内容更粗**，更依赖 VLM 接地 → 接地的成本与质量变成关键路径（见 `04` R13）。这解释了为什么"效率主张的支点是接地模型"。

如果将来要 S2，做法不是换聚类，而是**在 embedding 之外再加一个"段序"维度**（`02` 附录 A 记了三种方案：段序分位 / DTW 序列对齐 / HMM），届时再开。

### 2.3 实现细节（按你的做法 + 三条卫生要求）

**主流程**（就是你说的）：

```
全部 31,968 条 caption ──句向量编码器──> e_i (L2 归一化) ──K-means(N 簇)──> 簇 id
                                                                            │
每个 episode 的每段 → 继承该段的簇 id → 广播到该段覆盖的所有帧（绝对时间戳索引）
```

**三条卫生要求**（不满足会让簇退化，实测依据见下表）：

1. **L2 归一化再聚类**：句向量各向异性严重，不归一化时余弦被公共主方向吃掉 → 建议球面 k-means（质心归一化）。
2. **小写化 + 去句末句号**：实测 31.0% 带句号、13.2% 首字母大写，风格不统一。
3. **功能词抑制并检查质心可读性**：实测 TF-IDF 版 k-means 的质心前 4 词全是 `the / on / on_the / of`。换成密集句向量后要再查一次质心是否还是被功能词主导。

**实测参考**（`scripts/caption_structure.py`，313 段真实 caption，TF-IDF 代理句向量，仅用于看**结构**；真实运行要用密集句向量复算）：

| k | 得到的簇 | 平均簇内余弦 |
|---|---|---|
| 4 | pick(40.9%) / place(47.3%) / move(6.7%) / place-hang(5.1%) | 0.481 |
| 5 | pick(39.3%) / place-right(27.2%) / place-left(19.8%) / move+handover(11.8%) / headphones(1.9%) | 0.492 |
| 8 | 进一步按左右手与物体切（left-pick 23.6% / right-place 36.7% …），出现 5 段的极小簇 | 0.517 |
| 12 | 出现 2 段的退化簇（"return the ... resting position"） | 0.556 |

**读法**：k=5 给出干净的动词族；k≥8 开始按左右手/物体切，并出现单例簇；簇内余弦 0.48–0.56 说明**簇本身不紧**（同一个 "pick" 里还有左右手、物体、位置的差异）——这是密集句向量要改善的地方，也是 N 不宜太大的原因。

### 2.4 两个待定的小决策

| 项 | 选项 | 我的默认 |
|---|---|---|
| **N 怎么取** | 全库统一 N / 每任务各自 N | **全库统一 N = 5–8**（跨任务可迁移，对未见任务友好）；每任务各自 N 留作消融 |
| **聚类范围** | 35 个任务各聚一次 / 全库聚一次 | **全库聚一次**得到共享语义词表，再映射回任务；各任务独立聚会让簇互不可比 |

`[TBD-3]` = 仅剩"N 的具体取值"，建议先跑 N ∈ {5, 8, 12} 看轮廓系数与人读可读性再定。

## 3. 步骤 3：潜空间编码器 F `[已定]`

> **用户决议（2026-11-24）**：按原案 **V1 —— 每个子任务一个 VAE（+ 每任务一个）**，约 350 个。
> 我原来的反对意见有两条，其中**第二条在 conformal 判据下不成立**（我算错了），第一条仍然存在但可工程化解。下面按"V1 + conformal"重写这一节，这是本方案现在唯一自洽的读法。

### 3.1 为什么 V1 在 conformal 下是成立的（我此前的反对意见作废）

我原来的理由是"350 个独立 VAE 的潜空间互不可比，所以'当前 z 更像哪个子任务'无法提问"。**这个反对只在"用潜空间距离比较"时成立。** 而你选定的判据（`§4` conformal p 值）**根本不需要潜空间可比**：

- conformal 只需要每个子任务自己的一个**标量非一致性分数**，例如 `s_k(x) = −ELBO_k(x)`（第 k 个子任务的 VAE 对该观测的对数似然，越大越不像）；
- 每个子任务的 p 值都在**它自己的校准集**上算，于是每个 `p_k` 在原假设下**各自均匀分布**；
- 均匀分布的 p 值之间**天然可比**（这正是 conformal 处理多分类的标准做法）——`argmax_k p_k` 给出"最像哪个子任务"，`p_{k*} ≥ τ` 给出拒识判据。

**所以 V1 + conformal 是自洽的，甚至比全局 VAE 更贴合 conformal 的假设**（每个模型只对自己那一类负责，不要求跨类可比）。这一点是我此前推错的地方，已记录在 `DECISIONS.md` D2。

**顺带的好处**：官方评测里约 7 个任务从未出现在训练数据中（`01` §2）——它们没有自己的 VAE，"不存在任何子任务模型"直接落到 `task`/`cap` 分支，**OOD 兜底是架构自带的，不需要额外校准**。

### 3.2 剩下的一条真问题：样本量

每子任务 ≈ 5,900 帧（`stack_bowls`，100 集，见 `03` §3.1；不均衡时最小相位可能只有 ~1,000 帧）。5,900 帧训一个 VAE 会过拟合，除非把容量压下来。**这在工程上可解，但必须约束，否则 V1 会在 G3 静默失败（重建好看、判别无用）。**

| 约束 | 取值 | 理由 |
|---|---|---|
| 输入分辨率 | **96×128**（三视角各缩放） | 640×480 下参数/样本比必然过拟合 |
| 潜维 `d` | **16**（不要 32/64） | 样本量决定容量，降 d 比降层数更有效 |
| 骨干 | 小型 CNN（4 层 conv + BN），**不要 ResNet-18** | 1.1M 参数级；350 个模型也只要 ~0.4 GB |
| 正则 | 强增广（随机裁剪/颜色抖动）+ β 扫描（β ∈ {0.5,1,2,4}） | β 大 → 潜空间更规整，利于密度估计 |
| 校验 | **必做线性探针 + 留出集 ELBO gap** | 见 §3.4 的失败判据 |
| 每模型训练量 | 3,000–6,000 步（bs=64） | 单模型 3–6 min，350 个 ≈ 20–35 GPU·h（6c 单卡一夜） |

### 3.3 任务级 VAE（每个任务 1 个，共 35 个）也保留

按你的原案，**每任务再训一个 VAE**（53,100 帧，容量可以放大到 ResNet-18 + d=32）。它的作用不是"再判一次子任务"，而是：

- 提供 `p_task`：当前观测**是否符合整个任务**的分布（`§5.1` 的第二道闸）；
- 作为子任务 VAE 的**参照基线**：若 `p_task` 也不高，说明已经出任务分布 → 直接 CAP。

### 3.4 V1 的失败判据（必须在 G3 就抓住，不能拖到 G5）

每个子任务 VAE 训完后，逐模型检查三项，**任一不过就把该子任务降级为"无模型"**（路由时它会自动落到上级）：

1. **留出集 ELBO 不能显著差于训练集**（gap 超过 20% 视为过拟合，降 d 或加 β 重训）；
2. **重建的关节状态 MAE 要低**（状态重建加权 ≥2.0；若状态重建差，说明模型只学了图像，判别无用）；
3. **该子任务的校准集上，正样本的 p 值分布应接近均匀**（KS 检验 p 值分布——**这是 KS 唯一该用的地方**：检验 conformal 的校准是否有效，而不是拿 KS 做决策）。

### 3.5 明确写下来的代价

| 项 | V1 的代价 | 缓解 |
|---|---|---|
| 训练总量 | ~350 个小模型 ≈ 20–35 GPU·h | 6c GPU4 一夜；可用队列脚本并行（6 卡全空闲，见下） |
| 超参管理 | 350 组超参 | 全部固定同一套（分辨率/d/β/步数），只允许"降级为无模型"这一种变动 |
| 新增任务 | 新任务 = 需重训它的 N 个 VAE | 官方 42 任务里 7 个未见 → 设计上就走 CAP，不阻塞 |
| 与全局 VAE 的对比 | 无法做"跨任务共享表示"的实验 | 若审稿人要求，G3 阶段补一个全局 VAE 作对照（成本 1 天） |

## 4. 步骤 4：典型性判别 `[已定]`（换 conformal p 值）

### 4.1 为什么 KS 在这里不成立

设 `Z_k^cal = {z_i}` 为子任务 k 的校准集，`z_test` 为当前。原设想是"对 z_test 与 Z_k^cal 做 KS 检验"。四个独立的问题（**用户已决议改用 conformal，此处保留作为"为什么不能用 KS"的记录**）：

1. **维度**：KS 是 1 维检验（`sup_x |F_n(x) − F(x)|`）。`d=32` 时没有 1 维 CDF 可比；逐维做 32 次再取最小 p，就变成 32 重比较，power 崩且选择偏差严重。
2. **时序自相关（最致命）**：相邻帧高度相关，窗口内 `h` 帧的**有效样本量远小于 h**（2 s 窗口里独立样本可能只有 2–4 个）。KS 的 p 值假设 i.i.d.，在自相关下**严重反保守**：你会稳定得到 `p ≈ 0`，于是"永远不像任何子任务"，路由恒走 CAP。
3. **分布形状**：VAE 的聚合后验不是高斯；"潜空间是正态分布"只是先验假设，不是后验事实。
4. **多重检验**：N 个子任务各出一个 p 值，取最小者就是在做选择，未校正的阈值不再对应任何名义错误率。

### 4.2 替代方案（按推荐度）

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **C1 conformal p 值**（**推荐**） | 定义非一致性分数 `s_k(z)`（如到相位 k 样本中心的 Mahalanobis 距离，或 `−log p_k(z)`）；在相位 k 的**校准集**上算 p：`p_k = (1 + #{i: s_k(z_i) ≥ s_k(z_test)}) / (n_k + 1)` | 分布无关、**有限样本有效**、天然 1 维、阈值 τ 直接对应误拒率上界；同一框架天然处理"多子任务选一个"（对 N 个 p 取 argmax 即可，无需 Bonferroni） | 需要严格不相交的校准集；覆盖率是边际的，不是条件保证 |
| C2 能量距离 / MMD | 两样本检验统计量，任意维一致 | 无需分布假设，能比较整群 | p 值仍需置换检验（自相关下要 block permutation），且只有统计量没有"每类一个"的自然形式 |
| C3 单高斯 + Mahalanobis χ² | 每相位拟合 `N(μ_k, Σ_k)`，用 χ² 分位数出 p | 极简，1 个 p 值/相位，解析 | 强高斯假设，`Σ_k` 在 `d=32`、n≈6k 时需收缩估计（Ledoit-Wolf） |
| C4 C2ST | 训二分类器区分 `Z_k` 与 `z_test` | 最灵活 | 太贵，且不适合流式 |
| C5 KS（保留） | 1 维、按主成分投影或对照套边缘 | — | **只做诊断报告，不做决策** |

**推荐组合：C1 做主决策，C5 做诊断图。** 这一替换同时解决 `[风险 R1]` 与 `[风险 R7]` 的校准问题，也是本方案最可能拿得出手的方法贡献（见 `01` §6 贡献 2）。

### 4.3 历史 `h` 的取法 `[TBD-5]`

用户说"具体规则我之后给出"，但这是**先于所有实现的设计变量**：

| 取法 | 含义 | 预期 |
|---|---|---|
| `h = 1`（单帧） | 只看当前 | 相位歧义最大（很多相位视觉上无差别） |
| `h = 窗口 8 帧（0.32 s）` | 有短时运动 | 折中 |
| `h = {t−50, t−12, t}`（2 s / 0.5 s / 0 s） | 与既有 `SUBTASK_VLM_SPEC.md` 冻结规格同构 | **推荐**：与 VLM 打标/评测链路对齐，对照公平 |
| `h = 25 帧窗口（1 s）` | 连续窗口 | 与动作块下采样对齐 |

注意：无论哪种，**都必须在编码器里显式处理"补帧"**（时刻早于 episode 起点时用首帧并打标记，沿用 `SUBTASK_VLM_SPEC.md` §1 的做法），否则首个动作块总是被误判。

## 5. 步骤 5：路由决策与在线时序

### 5.1 三路决策

```
# 每 m 帧（慢层，1–2 Hz）执行一次
z      = F(x_t)                                  # ≤20 ms
p_k    = conformal_p(z, calib[k])  for k in 1..N  # 全部相位
k*     = argmax_k p_k
if p_{k*} >= τ_sub:      d = subtask(k*)
elif p_task(z) >= τ_task: d = task
else:                     d = cap
```

- `τ_sub, τ_task` **不是拍脑袋的常数**，由 `05` §3 的风险-覆盖曲线选取：横轴 = VLM/CAP 调用率，纵轴 = 离线路由准确率；取曲线上满足 J5（CAP 率 < 20%）的拐点。
- `p_task(z)` 是"是否符合整个任务分布"，用同一 conformal 框架在**任务级**校准集上算（相位标签换成任务标签）。

### 5.2 防抖三件套（缺一不可）

| 机制 | 参数 | 理由 |
|---|---|---|
| **确认帧数** | 连续 `m = 3–5` 次判别一致才切换 | VLA 的 action chunk 是 50 步（2 s），逐帧切换会造成语言条件在 chunk 内部反转 |
| **最小驻留** | `T_dwell = 1 s`（25 帧） | 与 chunk 边界对齐；避免在边界附近来回跳 |
| **CAP 冷却** | 触发后至少执行 1 个动作块再复评 | CAP 单次 3.4–5.6 s，抖动一次就吃掉全部效率收益（`[风险 R10]`） |

额外：**prompt latching** —— VLA 永远读当前锁存的 `π_t`，切换只在 chunk 边界发生，这样 VLA 闭环完全不受路由层影响。

> ⚠️ **这条设计现在没有依据（`04` R14）**：900 局实测显示 **chunk 边界刷新（`T+Vnow`）= 7.00%，显著有害（p=0.020）**，而更频繁的 step 级刷新（`T+Vnow-int10`）= 9.22%，与不注入打平。
> 所以"只在 chunk 边界换 prompt"恰恰是已测到的**最差**配置。但该实验把**刷新频率**与**动作视界**（chunk 被截断到 10 步）混淆了，不能直接推出"越勤越好"。
> **结论：latching 与"更勤刷新"两条路都保留，由 G2.5（异步刷新三臂）决定**（`05` §1、`PRIOR_RESULTS` §5）。在 G2.5 出结果前，不要把这个选择写进任何主张。

### 5.3 在线时序

```
时刻 t ────────────────────────────────────────────────────────────────>
 VLA  (10–14 Hz) │chunk│chunk│chunk│chunk│chunk│         每 chunk 68–71 ms
 慢层 (1–2 Hz)   ▲           ▲           ▲              每次 ≤20 ms + 无 VLM
 VLM/CAP         ▲(仅切换时，~8 次/局)                   接地: 0.4 s (2B) / 4.5 s (27B)
 π_t            ├── π1 ──────────┤── π2 ─────┤── π3 ──┤   锁存，只在 chunk 边界改
```

墙钟预算（单局，~21 s episode ≈ 9 个相位 ≈ **8 次切换**）。**这一块决定 A3 成不成立，必须按最坏情况算**：

| 接地后端 | 单次接地 | 8 次/局 | 总 s/局 | vs VLA-only | vs 每步 VLM (108 s) |
|---|---|---|---|---|---|
| 27B vLLM（现有链路） | 4.5 s | 36 s | **65 s** | **2.26×** ❌ | 0.60× ✅ |
| **2B 专用小模型**（`vlm-q3vl2b`，320px） | ~0.4 s（`估计`，待实测） | 3.2 s | **32 s** | **1.11×** ✅ | 0.30× ✅ |
| 异步（VLA 先用旧 prompt，接地回来再换） | 隐藏 ~80% | — | **~35 s** | 1.21× ✅ | 0.32× ✅ |
| 无接地（模板直出，`T+R*` 消融臂） | 0 | 0 | **28.8 s** | 1.00× ✅ | 0.27× ✅ |

**关键推论（原设想里没有的一步）**：路由只回答"现在是哪个相位"，而 prompt 还要**接地到当前场景**（哪个杯子、哪一侧——演示里的对象名未必对得上当前布局）。这次接地是 VLM 调用，**它的单次成本直接决定 A3**：

- 用 27B（现状链路 3.4–5.6 s）→ 每局 65 s，**比只给总任务慢 2.26×，J4 失败**，A3 只剩"比每步 VLM 快 1.7×"这一条弱的；
- 用自己已训好的 **2B**（`vlm-q3vl2b-s243k-320-1ep`，正是"看帧 + 任务 → 下一个子任务"这个任务）→ 32 s，**J4 通过**；
- **因此本方案的效率主张实际上是一个"小模型接地"的主张**，而不是"少调 VLM"的主张。既有 history5 的额外开销 79.2 s ÷ 4.5 s ≈ **17.6 次调用/局**（`估计`，由 108−28.8 反推），我们约 8 次，只少一半；真正的杠杆是单次成本降 10×。

这一点必须在立项时就说清楚，否则会被审稿人一句"你只是少调了两次"打掉。

**CAP 兜底的真实成本**（`CAP_LATENCY_NOTE.md`）：单次 **39.86 s** = 1.38× 单集 VLA 预算；全程 CAP ≈ 72 min/集。所以三路路由里 `cap` 分支的调用必须是 **O(1) 次/任务**，不能按决策步触发——否则墙钟直接 12×。

### 5.4 必须记录的运行时量（否则无法归因）

每次评测必须落盘：注入次数、切换次数、CAP 触发次数、慢层耗时分布、VLM 调用耗时分布、每相位的驻留时长分布。缺这些数字时，SR 差异无法区分"判别器准"与"碰巧"。

## 6. 小结：与原设想的差异（v0.2，含 2026-11-24 用户决议）

| 原设想 | 本文档 | 为什么 |
|---|---|---|
| 步骤 1 tokenizer → embedding | 句向量编码器（T-b），能取到 VLA 文本编码器则用 T-c | token 级池化语义分辨率不足；`[TBD-2]` |
| 步骤 2 句向量 K-means 得 N 个子任务 | **照做**（`[已定]`）。所得为 S1 语义类；S1 + VLM 接地 自洽 | 你的架构里接地由 VLM 负责，S1 足够；S2 只在"想把演示原句直接喂 VLA"时才需要 |
| 步骤 3 每子任务一个 VAE（≈350 个） | **照做**（`[已定]`）。必须配 conformal 判据（否则潜空间不可比），并用 96×128 / d=16 / 强增广压容量 | conformal 的 p 值各自均匀 → 跨模型天然可比（我此前的反对作废，见 `DECISIONS.md` D2） |
| 步骤 4 KS 检验 | **换 conformal p 值**（`[已定]`），KS 只用于校验校准有效性 | 高维 + 时序自相关使 KS 的 p 值塌到 0 |
| 步骤 5 三路路由 | 三路 + 确认帧数 + 最小驻留 + latching + CAP 冷却 | 缺防抖时语言条件抖动会直接吃掉 SR 与效率收益 |
| 步骤 5 的墙钟 | 效率主张改为"**接地用小模型**"，而非"少调 VLM" | 每局 8 次 vs 每步 VLM 的 ~17.6 次只差 2×；27B→2B 的单次成本差 10× 才是杠杆（`04` R13） |
