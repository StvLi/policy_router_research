# 路线 A：整任务 VAE 的潜空间 PCA 可视化（收纳耳机与笔记本电脑）

> 日期 2026-11-24 ｜ 脚本 `scripts/routeA_task_latent.py`（6c 导出）+ `scripts/routeA_pca_plot.py`（本地绘图）
> 问题：**用整条任务的帧训一个 VAE，把潜变量降到 3 个主成分，按子任务类别染色，能否看出任务在状态空间里的执行过程？**

---

## 1. 做法

1. 用路线 A 的冻结配置（3 相机当前帧 + `t/t−12/t−50` 关节状态、自重构、池化 3×4、隐维 16、关节权重 4.0）在**全部 10,366 帧**上训练**一个** task-level VAE（不再按子任务分类）。1,500 步，49,413 参数。
2. 取编码器的**均值 μ**（确定性，不用采样）作为潜变量，10,366 × 16。
3. 对 μ 做 PCA（SVD），保留 3 个主成分。
4. 按子任务类别（路线 A 的 5 类）染色，画 2D / 3D 散点与逐集轨迹。
5. 量化：解释方差、子任务可分性（3 维 vs 16 维）、PC1 与时间的关系、**相位（角度）与时间的关系**。

## 3. 看到的结果

### 3.1 潜空间里任务是一条**闭环**，类别是弧段

PC1–PC2 平面上点云排成一个明显的环（不是一个钟形/线形分布）。各类占据**相邻的弧段**：

| 类 | 代表句 | 在环上的位置 |
|---|---|---|
| c0 | grasp the right side of the tablet… | 下半环（最大的一段） |
| c1 | pick up the headphones from… | 右上弧段 |
| c2 | hand over the headphones… | 右上角，与 c1 相邻 |
| c4 | close the laptop on the black stand… | 左上弧段 |
| c3 | move both hands back… | 中心附近、点很少（该类只有 24 帧） |

**逐集轨迹**（`pca_trajectory.png`）显示：每一条 episode 都从环的一处出发，沿环走一段甚至绕回去，起点（绿色圆）与终点（红色方）落在不同位置。也就是说**"任务执行过程"在潜空间里表现为沿环的运动**，不是沿某条直线推进。

### 3.2 量化

| 指标 | 值 |
|---|---|
| 解释方差（PC1/2/3） | 16.5% / 12.7% / 10.4%（合计 **39.5%**） |
| 子任务 5 类可分性（softmax，留出 20 集） | 3 主成分 **74.9%** ／ 完整 16 维 **92.0%**（随机 20%） |
| 子任务可分性（最近质心） | 3 主成分 60.3% ／ 16 维 82.8% |
| 集内 Spearman(时间, **PC1**) | **−0.231**（abs(ρ)>0.5 的集仅 6%） |
| 集内 Spearman(时间, **展开角度**) | **−0.997**（abs(ρ)>0.7 的集 **92%**） |
| 每集绕环圈数 | 中位 **1.80** 圈 |
| 用 2 维（圆心投影）做 5 类 softmax | 65.9% |

**最重要的一条**：PC1 与时间几乎不相关（ρ=−0.23），但**展开后的角度与时间几乎完全单调（ρ=−0.997，92% 的集 abs(ρ)>0.7）**。

> **所以进度不是某个线性方向，而是绕环的"相位"。** 这也解释了为什么用 3 个主成分做线性分类只能到 75%（线性模型抓不住圆周结构），而完整 16 维能到 92%。

### 3.3 这与前面几条独立发现是一致的

- 路线 A 的"子任务类"判别能到 87.8%（按任务内 4 类），说明类确实可分；
- 但"阶段推进"是旋转而非直线 → 任何线性的"进度回归"都会失败；
- 也解释了为什么早期按"相对进度归一化"做的时间特征效果不好。

## 4. 对方案的影响（可执行的三条）

1. **路由的置信度特征应包含"相位"而不是只有类别后验。** 在 PC1–PC2 上算角度 θ 与半径 r，作为一个额外的低成本特征；同类别在不同圈数/不同转向时 θ 不同，可用来区分"同一动作的第二次发生"。
2. **相位可以做平滑的进度信号。** 角度与时间 ρ=−0.997，意味着它对"还剩多少步"有很强的解释力；这比现在"用子任务类别 + 停留时间"更直接。
3. **但不要把它当唯一信号**：中位 1.80 圈说明环会被绕多遍，角度与子任务不是一一对应（同一角度可能出现在不同类别），需要与类别后验联合使用。

## 7. 可拖动交互版（推荐先用这个建立直觉）

**`assets/latent_explorer.html`**（409 KB，单文件、零依赖、数据内嵌）——**双击用浏览器打开即可**，不需要服务器、不需要联网。

| 操作 | 效果 |
|---|---|
| 左键拖动 | 旋转（yaw / pitch） |
| 滚轮 | 缩放 |
| 右键或 Shift+拖动 | 平移 |
| 双击 / 「重置视角」 | 回到等轴测 |

| 功能 | 说明 |
|---|---|
| **着色方式** | 子任务类别 / **相位角** / 时间 / 不典型度 / episode |
| **子任务勾选** | 逐个显隐 5 个类，单独看某一类在环上的位置 |
| **轨迹** | 选一条 episode，画出它的执行路径（线段按时间渐变，绿点=起点、红方=终点） |
| **淡化其它点** | 只看该集，配合轨迹 |
| **视角预设** | 等轴测 / 看 PC1-PC2 / 看 PC2-PC3 / 看 PC1-PC3 —— 快速建立"这是一条闭合环"的立体感 |
| **自动旋转** | 缓慢绕轴旋转，便于看出环状结构 |
| 悬停 | 显示该点的 episode、时间、类别、相位角、不典型度 |
| **head 视频循环播放** | 选中某条 episode 后，左上角出现该集的头部相机视频（320×240，12 fps），**自动循环播放** |
| **进度条** | 视频下方有可拖动进度条，随意跳到某一段；显示当前时间 / 总时长 |
| **视频 ↔ 轨迹同步** | 播放或拖动进度条时，3D 轨迹上的游标跟着动；下方实时显示当前段落的 caption 与类别色块 |
| **两栏对照** | 左栏 = 训练数据（按子任务着色）；右栏 = **VLM-VLA 联合评测轨迹（白点）**，两栏共享同一相机与坐标系，拖动任一栏另一栏同步转 |

比静态图多出来的两件事：

1. **绕到别的角度就能确认它真是环**，而不是投影造成的假象（静态 2D 图给不出这个判断）；
2. **切到"相位角"着色**后，颜色沿环连续变化，能直接看出"角度＝进度"这件事；再切到"时间"着色，两者几乎一致。

生成方式（需要 Python + numpy，不需要浏览器）：

```bash
python3 scripts/make_latent_explorer.py --latent /tmp/routeA_task_latent.npz \
        --out docs/assets/latent_explorer.html
```

> 纯 Canvas 2D + 手写投影与深度排序。**静态层（点云/轴/轨迹）在视图变化时渲染到离屏画布并缓存**；
> 播放视频时每帧只做一次 `drawImage` + 画游标，所以 10,366 个点也能流畅播。

### 7.0 右栏：评测轨迹（当前全部白点）

右栏放的是 `store_laptop_and_headphones` 任务的 **50 个评测 rollout**（25 个布局 × `T` / `T+Vnow` 两种配置），共 **7,828 帧**，文件名里带 success/fail。
目前**全部画成白点**（外加淡淡的连线，可关），还没有按成功/失败上色。

**⚠️ 这一栏是"近似投影"，读的时候必须知道代价：**

| 评测侧实际有的 | 缺失的 | 这里怎么补 |
|---|---|---|
| head 相机视频（25 fps） | **左右腕视角**、**关节状态** | 为每个评测帧找**最相似的演示帧**（head 画面 4×5 网格 RGB 均值描述子的最近邻），借用它的左右腕画面与 `t/t−12/t−50` 状态窗口 |

三个后果：

1. **评测点会被拉向"看起来像的那批演示帧"** → 右栏的点云形态主要由"像哪些演示帧"决定，**不能**用它判断"策略偏离了演示分布多远"。
2. **骨架和演示是同一套**（它们本来就是演示帧的状态），所以右栏的形状不代表真实轨迹的动力学。
3. 因此**目前只能做定性观察**（成功/失败的 rollout 是否落在大致不同的区域），不能据此下定量结论。

**要拿到可信版本，需要**：重新跑一遍评测并把每步的 `observation.state` 与三路画面落盘（评测 harness 现在只存 head 视频 + `_result.json`），然后直接过同一个 VAE 即可——`scripts/routeA_project_eval.py` 里把"最近邻插补"换成"读真实观测"就行。

生成方式：

```bash

CUDA_VISIBLE_DEVICES=4 $L scripts/routeA_project_eval.py --videos /tmp/eval_clips
```

## 5. 边界（必须一起读）

1. **只有一个任务**，且该任务的句子高度模板化；换任务形状可能不同（未必是闭环）。
2. **1.80 圈的解读有保留**：若轨迹经过圆心附近（半径小），角度定义不稳定，展开时会累积虚假圈数。左图显示多数时间半径较大，但靠近中心的片段仍需谨慎。
3. **PCA 是线性降维**：环结构可能是 16 维里更高维结构的投影；UMAP/t-SNE 未尝试（环境无 sklearn）。
4. 全部基于**演示帧**，不是闭环 rollout。闭环时策略自己决策，轨迹可能不再闭合。
5. 5 类里的 c3（收尾复位）只有 24 帧，在图上几乎看不到，统计上可忽略。
